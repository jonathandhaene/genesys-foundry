# ServiceNow Integration

## Integration Overview

ServiceNow is the leading ITSM platform for enterprise IT service desks and increasingly for customer service operations. Contact Center Foundry integrates with ServiceNow via the **ServiceNow REST API**, **Table API**, and **Now Platform Events**.

---

## Authentication

- **OAuth 2.0 Password Flow** or **OAuth 2.0 Client Credentials** (recommended for production)
- Dedicated ServiceNow integration user with minimum required roles
- Credentials stored in Azure Key Vault

**Required ServiceNow Roles:**

| Role | Reason |
|---|---|
| `itil_read` | Read incidents, requests, problems |
| `kb_reader` | Read knowledge base articles |
| `rest_api_explorer` | API access |
| (Custom write role) | Create work notes on incidents/requests |

---

## Read Operations (ITSM Context)

At interaction start:

```
// Incident lookup by caller email
GET /api/now/table/incident?
  sysparm_query=caller_id.email={email}^stateNOT IN6,7^
  sysparm_fields=sys_id,number,short_description,state,priority,opened_at,assignment_group&
  sysparm_limit=5&
  sysparm_order_by_direction=DESC&
  sysparm_order_by=opened_at
```

**Data retrieved:**

| Data | ServiceNow Table | Purpose |
|---|---|---|
| Caller record | `sys_user` | Identity resolution |
| Open incidents | `incident` | Current IT issues |
| Open requests | `sc_request` | Pending service requests |
| CMDB assets | `cmdb_ci` | IT assets linked to user |
| SLA records | `task_sla` | SLA breach risk |
| Change calendar | `change_request` | Upcoming changes affecting user |

---

## Real-Time Events (ServiceNow Events)

ServiceNow **Business Rules** or **Flow Designer** can push outbound webhook events to the Integration Gateway:

| Event | Trigger | Platform Action |
|---|---|---|
| `incident.created` | New incident for a contact | Alert agent if customer is on active call |
| `incident.resolved` | Incident resolved | Update agent context; suggest proactive notification |
| `major_incident.declared` | Major incident declared | Broadcast alert to all relevant agent sessions |
| `change.go_live` | Emergency change approved | Alert supervisor team |

## Write Operations

### Work Note on Incident

```
PATCH /api/now/table/incident/{sys_id}
{
  "work_notes": "AI Interaction Summary ({datetime}):\n\n{summary}\n\nSources: {sources}\n\n[Generated by Contact Center Foundry AI — Interaction: {interactionId}]",
  "u_ai_interaction_ref": "{interactionId}"
}
```

### New Incident from Chat/Email

When an agent creates a new incident during an interaction, the AI can pre-populate the incident fields:

```
POST /api/now/table/incident
{
  "short_description": "<AI-extracted issue title>",
  "description": "<AI-generated description from interaction>",
  "caller_id": "{sysId}",
  "category": "<AI-classified category>",
  "subcategory": "<AI-classified subcategory>",
  "urgency": "<AI-assessed urgency>",
  "u_interaction_ref": "{interactionId}"
}
```

## Knowledge Base Integration

ServiceNow Knowledge Base articles are indexed into the knowledge layer:

```
GET /api/now/table/kb_knowledge?
  sysparm_query=workflow_state=published^
  sysparm_fields=sys_id,short_description,text,kb_category,sys_updated_on,u_language&
  sysparm_limit=500
```

- Paginated retrieval for large knowledge bases
- Category hierarchy preserved for contextual filtering
- User criteria (access control) honoured at query time via ServiceNow API

---

## Major Incident Support

During a major incident, the platform can:

1. **Broadcast** a brief to all agent sessions: "Major incident declared — P1 network outage affecting EU customers. ETR: 60 minutes. Do not raise new incidents; link to MI INC0012345."
2. **Pre-load** the major incident knowledge into agent copilot context
3. **Accelerate** new incident triage by suggesting the major incident link

## Configuration Reference

```yaml
connector:
  id: servicenow-prod
  type: servicenow
  instance_url: https://yourorg.service-now.com
  auth:
    type: oauth2_password
    client_id_secret: kv://snow-client-id
    client_secret_secret: kv://snow-client-secret
    username_secret: kv://snow-integration-username
    password_secret: kv://snow-integration-password
  features:
    context_load: true
    knowledge_index: true
    work_note_writeback: true
    incident_prepopulate: true
    major_incident_broadcast: true
  knowledge:
    refresh_interval_hours: 2
    categories:
      - "IT Support"
      - "HR Services"
      - "Facilities"
```
